# Evaluation assets

## `data/` — gold corpora (JSONL, one case per line)

| Corpus | Shape | Used by |
| --- | --- | --- |
| `results.jsonl` | `{id, text, context, occurrences, error?}` | `evals.rs` — end-to-end occurrence equality |
| `grammar.jsonl`, `grammar-variations.jsonl`, `adversarial.jsonl`, `negatives.jsonl`, `prose.jsonl` | `{id, family, text, schedule}` | `evals.rs` — model output must assemble the recorded schedule (`schedule: null` expects no expression) |
| `labels.jsonl` | `{id, text, tokens, schedule}` | `oracle_cases.rs` — compiler-only oracle with hand labels |
| `user-cases.jsonl` | `{id, text, context, occurrences}` | `runtime_cases.rs` tokenizer losslessness |

The corpora encode schedules in the same JSON shapes the library's serde
implementation reads and writes (internally tagged by `kind`, camelCase
fields, optional fields omitted), so they double as an encoding contract —
`runtime_cases.rs` round-trips every schedule through the encoding.

## `active/` — numeric model parity fixtures (binary, little-endian)

| File | Contents |
| --- | --- |
| `transformer-parity.rows.bin` | `u16` feature rows, 17 per token, per-sequence (unpadded) |
| `transformer-parity.lengths.bin` | `u32` token counts, one per sequence |
| `transformer-parity.logits.bin` | `f32` reference logits, 41 per token (40 roles + boundary), computed from the int8-quantized weights |

`transformer_parity.rs` replays these through `model/transformer.rs` and
gates on argmax agreement and logit drift below 2e-3. They are regenerated
by the training pipeline (`train_transformer.py`, families in
`transformer_families.py`).

## Refreshing

These assets move together with `../what-time/assets/weights-transformer.json`:
after training a new checkpoint the export writes both files; re-record the
corpus expectations if behavior changed. `cargo
test` fails closed if predictions shift. `multilingual.jsonl` holds the
English/Hindi/Hinglish expectations frozen by the `freeze-multilingual`
example.
